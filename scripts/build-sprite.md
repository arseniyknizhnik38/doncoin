# Как собраны спрайты персонажей

`client/public/don-*.webp` — ленты из 8 кадров, вырезанные из исходных видео. Видео в проект не кладём: каждое
весит несколько мегабайт и грузилось бы каждую сессию, а лента — около 140 КБ.

Инструменты нужны только для пересборки, в зависимостях проекта их нет:

```bash
npm i -D pngjs
npx --yes ffmpeg-static --version >/dev/null 2>&1 || true
```

`ffmpeg-static` намеренно не записан в зависимости проекта: он качает около
80 мегабайт бинарника при каждой установке, включая сборку на Vercel, где
видео никто не режет. Один раз уже уронил `npm install` обрывом соединения.
Нужен он только здесь, поэтому и ставится разово:

```bash
npm i -D --no-save ffmpeg-static
```

## 1. Выбрать отрезок, который зациклится

Анимация крутится по кругу, пока игрок тапает, поэтому последний кадр должен
переходить в первый без рывка. Разложите видео на кадры и найдите окно, где
стык не больше обычного шага между соседними кадрами:

```bash
npx ffmpeg -y -i ИСХОДНОЕ_ВИДЕО.mp4 -vf "fps=8" all/f%03d.png
```

Дальше окно подбирает скрипт:

```bash
node scripts/find-sprite-loop.mjs all
```

Он сравнивает кадр `s` с кадром `s+8` («стык») и со средней разницей соседних
кадров внутри окна («шаг»). Выбирает окно с наименьшим стыком среди тех, где
движение не слабее половины типичного: маленький стык при неподвижности
означает, что персонаж просто замрёт.

Отношения стыка к шагу как единственного критерия не хватает. У «Капо» окно
с лучшим отношением (1.69) имело стык 14.1, а соседнее с отношением похуже
(1.87) — стык 9.1: прыжок вдвое слабее при том же оживлении. Видимость рывка
задаёт абсолютная величина стыка, а не её отношение к чему-либо.

Если в исходнике чистой петли нет вовсе, скрипт об этом скажет. У «Капо» так
и вышло: лучший стык вдвое крупнее шага, и небольшой рывок на повторе виден.
Исправляется это не нарезкой, а исходником — нужна зацикленная анимация.

Заодно скрипт печатает цвет фона и габариты фигуры: они нужны на следующем
шаге, чтобы посчитать `scale` и `pad`.

## 2. Вписать фигуру в кадр 192×192

Все персонажи должны быть одного роста и стоять на одной линии, иначе смена
ранга выглядит как подмена, а фигура подскакивает. Ориентир: **рост 170,
нижний край на строке 188**, центр фигуры по горизонтали около 96. Ширина
свободная — она зависит от позы и телосложения (от 65 у «Солдата» с руками
перед собой до 97 у «Приближённого» в объёмной куртке).

Проверять глазами это бесполезно: разница в три пикселя не видна на картинке,
но заметна при смене ранга. Померьте готовую ленту и сравните с соседними —
у «Солдата» с первого раза вышло 167 и линия ног на 185, то есть он висел бы
на три пикселя выше остальных.

Исходник обычно портретный, поэтому масштабировать «в квадрат» нельзя —
персонаж расплющится. Сжимаем с сохранением пропорций и досыпаем поля цветом
фона (их всё равно срежет заливка):

```bash
npx ffmpeg -y -start_number 18 -i all/f%03d.png -frames:v 8 \
  -vf "scale=128:192:flags=neighbor,pad=192:201:34:9:color=0xF9FAFD,crop=192:192:0:0" \
  frames/f%02d.png
```

`flags=neighbor` — масштабирование без сглаживания: иначе фон подмешивается в
края фигуры и после вырезания остаётся светлая кайма. Числа в `scale`, `pad` и
`crop` считаются под конкретное видео — от размера фигуры в исходных кадрах.

## 3. Вырезать фон

```bash
node scripts/cut-sprite-background.mjs frames strip.png --shadow
```

Скрипт заливает прозрачностью **только связную область от краёв кадра** и
останавливается на тёмном контуре персонажа.

Так сделано не случайно: первая версия убирала все пиксели, похожие на цвет
фона, и вместе с фоном исчезли белки глаз и белая майка — они оказались
достаточно близки к нему по цвету.

`--shadow` нужен, если под ногами в исходнике нарисована тень: на фоне
приложения она читается как грязное пятно.

Полоса яркости, по которой ищется тень, задана долей от яркости фона, а не
абсолютными числами. Сначала числа были абсолютными и молча подходили только
светлым исходникам: у «Солдата» фон тёмный, тень на нём яркостью около 55 при
фоне 90, в старую полосу (175..232) не попадала, и мазок оставался. Отличать её от белых кроссовок
по близости к фону нельзя — кроссовки к белому фону ближе, поэтому исчезли бы
первыми. Признак другой: тень нейтрально-серая, средней яркости и лежит в самом
низу кадра.

Тень заодно запирает фон между ногами, куда заливка от краёв не достаёт, — из-за
этого после первого прохода там оставался белый лоскут. Поэтому с `--shadow`
скрипт проходит краевой заливкой ещё раз, уже сквозь вырезанное.

## 4. Собрать в WebP

```bash
npx ffmpeg -y -i strip.png -c:v libwebp -lossless 1 client/public/don-НОВЫЙ.webp
```

Сжатие без потерь: у пиксель-арта на границах иначе появляется грязь.

## Добавить персонажа новому рангу

Одна строка в `client/src/game/TapCoin.tsx`, в `RANK_SPRITES`. Ранга нет в
списке — показывается монета.

## Если меняется число кадров

Поправьте в двух местах:

- `client/src/index.css` — ширину `.don-strip` (`800%` = 8 кадров);
- `client/src/game/TapCoin.tsx` — константу `SPRITE_FRAMES`.

## Почему смена кадров сделана в коде, а не в CSS

Два подхода уже сломались, и оба одинаково — персонаж пропадал при тапе.

**`background-position` в процентах.** Там процент считается от разницы
размеров картинки и элемента, а не от ширины кадра. При ленте из восьми
кадров «шаг на 100%» уводил её сразу за границы.

**CSS-анимация со `steps()` по `transform`.** На десктопе работала верно, а на
мобильных движках последний шаг иногда отрисовывается конечным значением
ключевого кадра (`-100%`), и лента снова уезжает целиком из окна.

Сейчас номер кадра лежит в состоянии компонента, сдвиг считается явно
(`кадр × 12.5%` от ширины ленты), а таймер крутится только пока идут тапы.
Это ведёт себя одинаково во всех движках.

## Пример: как собран «Солдат»

Исходник 624×624, 24 кадра в секунду, 5 секунд. Фон 0x555167, фигура в кадре
332×575.

```bash
npx ffmpeg -y -i ИСХОДНИК.mp4 -vf "fps=8" all/f%03d.png
node scripts/find-sprite-loop.mjs all          # лучшее окно: кадры 28..35

npx ffmpeg -y -start_number 28 -i all/f%03d.png -frames:v 8   -vf "scale=188:188:flags=neighbor,pad=192:200:2:12:color=0x555167,crop=192:192:0:0"   frames/f%02d.png

node scripts/cut-sprite-background.mjs frames strip.png --shadow
npx ffmpeg -y -i strip.png -c:v libwebp -lossless 1 client/public/don-soldier.webp
```

Итог: рост 170, нижний край 188, 118 КБ.

## Пример: как собран «Капо»

Исходник 512×768 (портретный), фон светло-серый 0x9598A1, тень упирается
в нижний край кадра — в высоту фигуры она не входит, поэтому масштаб
подбирался по готовой ленте, а не по габаритам из скрипта.

```bash
npx ffmpeg -y -i ИСХОДНИК.mp4 -vf "fps=8" all/f%03d.png
node scripts/find-sprite-loop.mjs all          # лучшее окно: кадры 33..40

npx ffmpeg -y -start_number 33 -i all/f%03d.png -frames:v 8   -vf "scale=120:180:flags=neighbor,pad=192:194:28:12:color=0x9598A1,crop=192:192:0:0"   frames/f%02d.png

node scripts/cut-sprite-background.mjs frames strip.png --shadow
npx ffmpeg -y -i strip.png -c:v libwebp -lossless 1 client/public/don-capo.webp
```

С первого раза вышло 173 при нижнем крае 190 и центре 100 — подгонялось
двумя итерациями. Итог: рост 170, нижний край 188, центр 96, 152 КБ.

# Фоны рангов

Персонажи рангов — намеренно разные люди, поэтому «стал богаче» по самой
фигуре не читается. Это берёт на себя обстановка за спиной: подворотня,
ресторан, кабинет. Повышение видно раньше, чем игрок прочитает надпись.

```bash
node scripts/build-background.mjs ИСХОДНИК.png soldier
```

Скрипт обрежет по центру до 9:16, уменьшит до 720×1280 без сглаживания и
закодирует в WebP без потерь. Останется добавить строку в
`client/src/game/RankBackdrop.tsx`.

## Что нужно от исходника

**Соотношение 9:16, сюжет в середине.** Телефоны бывают от 9:16 до 9:20 с
лишним, картинка показывается «по обложке» — края обрежутся, и на каком
аппарате сколько, заранее неизвестно.

**Пустая середина.** Ровно там стоит персонаж, и он занимает до 256 точек по
высоте. Вензеля и лица за его спиной не увидит никто.

**Тёмный верх и низ.** Сверху лежат имя, ранг и баланс, снизу — обойма и
вкладки. Скрипт затемнения не добавляет: поверх картинки лежит градиент из
`RankBackdrop`, но если исходник светлый, золотой текст на нём всё равно
поплывёт.

**Крупное зерно.** Фигура нарисована блоками; гладкий фон за ней выглядит как
фотография, к которой приклеили пиксель-арт. Просите пиксель-арт и не
просите деталей — они всё равно не переживут уменьшения до 720 точек.

**Никакого горизонта по центру.** Пол должен приходиться примерно на нижнюю
треть: персонаж стоит там, и если линия пола проходит по его коленям, он
выглядит вкопанным.

## Вес

Фон грузится каждую сессию. Спрайт персонажа весит около 140 КБ, фон стоит
держать в тех же пределах; выше 400 КБ скрипт предупредит. У пиксель-арта
вес растёт от числа цветов и мелкой ряби, а не от размера картинки — если
получилось тяжело, уменьшать надо детализацию, а не разрешение.

## Пример: как собран «Аутсайдер»

Исходник 624×624, фон 0x5F5952, фигура в кадре 284×557. Петля чистая:
стык 4.82 при шаге 4.75.

```bash
npx ffmpeg -y -i ИСХОДНИК.mp4 -vf "fps=8" all/f%03d.png
node scripts/find-sprite-loop.mjs all          # лучшее окно: кадры 5..12

npx ffmpeg -y -start_number 5 -i all/f%03d.png -frames:v 8   -vf "scale=191:191:flags=neighbor,pad=192:196:1:5:color=0x5F5952,crop=192:192:0:0"   frames/f%02d.png

node scripts/cut-sprite-background.mjs frames strip.png --shadow
npx ffmpeg -y -i strip.png -c:v libwebp -lossless 1 client/public/don-outsider.webp
```

На нём вскрылось, что тень распознаётся не всегда: здесь она тёмно-бирюзовая,
вдвое темнее фона и слишком цветная для проверки. Тень осталась, а с ней и
серый лоскут между ног — заливка от краёв туда не пробилась. Теперь скрипт
отдельно снимает фон, запертый внутри фигуры: ниже середины кадра и уже пятой
части ширины. Выше середины он не трогает ничего — там глаза и рубашка, на
которых прошлая версия уже обжигалась.

Итог: рост 170, нижний край 188, 112 КБ.

## Пример: как собран «Консильери»

Исходник 624×624, 24 кадра в секунду, 5 секунд. Фон 0x40484D, фигура в кадре
272×590. Единственный из четырёх, где петля нашлась чистая: стык 7.36 при
шаге 7.44 — рывка на повторе не видно.

```bash
npx ffmpeg -y -i ИСХОДНИК.mp4 -vf "fps=8" all/f%03d.png
node scripts/find-sprite-loop.mjs all          # лучшее окно: кадры 14..21

npx ffmpeg -y -start_number 14 -i all/f%03d.png -frames:v 8 \
  -vf "scale=180:180:flags=neighbor,pad=192:193:10:12:color=0x40484D,crop=192:192:0:0" \
  frames/f%02d.png

node scripts/cut-sprite-background.mjs frames strip.png --shadow
npx ffmpeg -y -i strip.png -c:v libwebp -lossless 1 client/public/don-consigliere.webp
```

С первого раза нижний край вышел на 187 — на пиксель выше остальных, поэтому
отступ сверху в `pad` стал 12. Итог: рост 170, нижний край 188, 105 КБ.

## Пример: как собран «Дон»

Исходник 624×624, фон 0x3B4D5C, фигура в кадре 330×547 и заметно смещена
вправо — она держит букет, и центр тяжести кадра уехал вместе с ним.
Поэтому здесь, в отличие от остальных, пришлось двигать кадр по обеим осям:
`pad` опускает фигуру на две точки, `crop` сдвигает её влево на 51.

```bash
npx ffmpeg -y -i ИСХОДНИК.mp4 -vf "fps=8" all/f%03d.png
node scripts/find-sprite-loop.mjs all          # лучшее окно: кадры 8..15

npx ffmpeg -y -start_number 8 -i all/f%03d.png -frames:v 8 \
  -vf "scale=195:195:flags=neighbor,pad=246:197:33:2:color=0x3B4D5C,crop=192:192:51:0" \
  frames/f%02d.png

node scripts/cut-sprite-background.mjs frames strip.png --shadow
npx ffmpeg -y -i strip.png -c:v libwebp -lossless 1 client/public/don-don.webp
```

Центр меряется по всей фигуре вместе с букетом, поэтому сам человек стоит
чуть левее середины — так и надо: иначе букет выпирал бы за край кадра.

Вырезать его пришлось на других настройках, и это единственный такой случай:

```bash
node scripts/cut-sprite-background.mjs frames strip.png --shadow --tolerance 22 --no-gaps
```

Фон у исходника тёмно-синий, а штаны почти чёрные с синевой. На обычном
допуске в 42 заливка прошла сквозь ткань и выела в штанинах дыры, а проход,
снимающий запертый между ног фон, довершил дело — в игре Дон стоял драный.
Допуск 22 отделяет ткань от фона, `--no-gaps` выключает тот самый проход:
между ног у этой позы фон и так открыт с краёв.

Итог: рост 170, нижний край 188, 149 КБ.

# Проверка вырезки

Разглядывать контур глазами бесполезно: дыры в тёмной одежде и мелкий мусор
по краям видно только при увеличении, а в игре они читаются как грязь. Поэтому
есть счётчик:

```bash
npx ffmpeg -y -i client/public/don-capo.webp /tmp/capo.png
node scripts/check-sprites.mjs /tmp/capo.png
```

Он ищет два вида брака:

- **дыры** — прозрачные пятна внутри фигуры от 4 до 60 точек. Крупнее — это
  обычно просвет между ногами, снятый намеренно, поэтому он не считается;
- **мусор** — куски, не связанные с телом: остатки фона и тени.

У готового персонажа оба числа нулевые. Если дыр много и они мелкие — заливка
прошла сквозь одежду, нужен меньший `--tolerance`.
